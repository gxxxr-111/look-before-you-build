# look-before-you-build

[English](README.md) | **简体中文**

> **状态：v0.1，实验性。** 评测集还很小，自动触发率偏低。详见[目前的结论](#目前的结论)。

一个 Claude Code skill（`preflight`），专门补上编码智能体最常跳过的一步：**元研究（meta-research）**。动手写代码*之前*，先判断这件事值得想多深，然后只想到那个程度。

## 要解决的问题

让智能体"做个游戏 AI"，它会不停堆砌启发式规则；让它"写个爬虫抓字幕"，它就真去写爬虫，却不先查有没有官方字幕接口或成熟工具。代价最高的错误很少是代码写得烂，而是：

- **问题归类错了**：本该用 minimax / MCTS 解决的搜索问题，却靠手调规则硬补；
- **漏掉了现成方案**：官方 API、标准库，或者已有的 skill / MCP server；
- **资源获取路径太贵**：还没看文档、sitemap 或结构化数据，就先上了浏览器自动化；
- **架构锁死、难以回退**：数据格式、数据库 schema、对外接口；
- **人被甩在后面**：非技术背景的人看不懂、否决不了、也无法真正对关键决策负责。

代码审查（code review）是在代码写出来*之后*把关。这个 skill 管的是前一步：决定做什么、怎么做——大部分返工都源于这里。

## 它做什么

1. **给任务分级**（0 / 1 / 2），依据是可逆性、影响范围、外部依赖和不确定性。0 级直接做，不走任何流程。
2. **按级别决定研究深度。** 一份六维清单：问题定性、现有方案、获取路径、架构、工具、人的掌控。2 级任务会并行派出三个子智能体，分别负责问题归类、现有方案调研、低成本的环境侦察。
3. **写一页纸的简报**，用大白话，附上可运行的验证方式，以及每个关键决策（选了什么、放弃了什么、以后改的代价多大）。
4. **先问，还是先做？** 用户事后无法轻易撤销的决策（第三方服务条款、账号、花钱、schema、数据迁移、方向性分岔）先等确认；可逆的决策直接做出来并验证，再*连同*简报一起交给用户。判断标准：*如果用户看到结果后不同意，他会损失多少？*
5. **中途及时退一步**：同一类问题修了三轮还没好、连续两次被否、补丁越来越依赖特例、或者某个前提被证伪时，停下来重新研究。
6. **复盘。** 每次收尾都问一句：*当初如果先问了哪个问题，能省下最多的返工？* 答案写进项目的 `PREFLIGHT.md` 或你的个人经验文件。

部分灵感来自 Anthropic 关于 [Claude Code 团队如何做代码审查](https://claude.dev/blog/solving-code-review-at-anthropic/) 的文章：按风险投入精力、要求可运行的验证、限制来回轮数、把每次事故反馈进流程。本项目与 Anthropic 无关联。

## 安装

作为插件安装（推荐）：

```
/plugin marketplace add gxxxr-111/look-before-you-build
/plugin install look-before-you-build@look-before-you-build
```

或者手动复制 skill 目录：

```bash
git clone https://github.com/gxxxr-111/look-before-you-build
cp -R look-before-you-build/skills/preflight ~/.claude/skills/preflight
```

### 让它真正被触发

遇到"帮我做个 X"这类请求时，Claude 很少主动调用这个 skill（见下文）。在 `~/.claude/CLAUDE.md` 或项目的 `CLAUDE.md` 里加一行即可：

```markdown
开始新项目或新功能、对接外部网站/API、写爬虫或自动化、做技术栈/架构选型之前——或者同一个 bug 修了三次还没好时——使用 preflight skill。
```

## 经验文件放在哪

| 文件 | 内容 | 更新后是否保留 |
|---|---|---|
| `skills/preflight/references/lessons.md` | skill 自带的初始经验 | 更新时会被覆盖 |
| `~/.claude/preflight/lessons.md` | 你自己的跨项目经验 | 保留 |
| `<项目>/PREFLIGHT.md` | 项目特有的坑和检查项 | 保留 |

## 目前的结论

用 Anthropic 的 skill-creator 流程评测，每种配置只跑了一次——请当作早期信号，而不是定论。

| 用例 | 使用 skill | 不使用 skill | 说明 |
|---|---|---|---|
| `rename-function-tier0`（简单重命名） | 3/3 | 3/3 | 两者都没走多余流程，说明 0 级确实够轻 |
| `gomoku-stuck-reframe`（调了 5 次权重仍失败） | 5/5 | 5/5 | 两者都转向了搜索算法，暂时区分不出差异 |
| `transcript-tool-tier2`（批量获取 B 站视频文字稿） | 6/6 | 3/6 | 使用 skill 时基于现有工具构建、写了离线测试，并在涉及登录/服务条款的决策前停下 |

**自动触发偏弱。** 在 20 条查询上（10 条应触发、10 条相近但不应触发），精确率 100%，召回率仅 0–17%；改写描述五轮，在留出集上都没超过原版。建议使用上面那行 `CLAUDE.md` 配置。

详情见 [`evals/RESULTS.md`](evals/RESULTS.md)（英文）。非常欢迎贡献更难、更有区分度的用例。

## 运行评测

```bash
claude plugin eval .
```

每次运行都会启动真实的智能体会话、消耗真实的 token（完整跑一遍约几十万）。迭代时建议只跑单个用例。
